# Idiomas (i18n)

Ativos hoje: **português** (padrão e fonte) e **inglês**. Os outros seis (es, fr, de, it, ja, zh-CN) têm dicionários de interface em `src/i18n/ui/`, mas estão fora de `LOCALES` e de `DICTS`, então não aparecem no seletor. O que falta para reativá-los está em `docs/CHECKLIST.md`, na seção "Traduções: o que falta".

## Interface: dicionários

- `src/i18n/ui/pt.ts` é a fonte. `export type UIKey = keyof typeof pt`.
- Cada dicionário é `Record<UIKey, string>`. Se você adicionar uma chave em `pt` e esquecer um idioma, o typecheck quebra. Para cada chave nova, adicione em **todos** os dicionários de `src/i18n/ui/` (os inativos recebem o português até serem traduzidos).
- Uso: `t('chave')` ou `t('chave', { nome: valor })`. Variáveis são `{nome}`.
- **Regra das variáveis:** a tradução precisa ter exatamente as mesmas variáveis do português. O teste `src/__tests__/i18n.test.ts` confere isso.
- `t()` lê o idioma atual de `src/i18n/state.ts`.
- `DICTS` em `src/i18n/index.ts` lista só os idiomas ativos.

## Idioma atual e troca

- `LOCALES` em `src/i18n/locales.ts` define o seletor. `DEFAULT_LOCALE` é `pt`.
- `store.setLocale(locale)` grava no `localStorage` e chama `setCurrentLocale`.
- `App.tsx` remonta a árvore com `key={locale}`. Por isso, qualquer dado calculado no carregamento do módulo fica desatualizado: use funções que leem o idioma na hora da chamada, e caches indexados pelo idioma.
- Estados de painel (gaveta, FAQ, Sobre) ficam na store, então sobrevivem à troca de idioma.

## Conteúdo traduzido: overlays

O português mora nos arquivos de dados. Um overlay traduz por cima, por idioma:

- `src/i18n/content/index.ts`: `OVERLAYS` (um overlay por idioma).
- `src/i18n/content/types.ts`: os formatos (`SkillOverlay`, `StepOverlay`, `FaqOverlay`, `TierOverlay`, `StatusOverlay`, `BenchmarkOverlay`).
- `src/i18n/content/en.ts`: habilidades em inglês (`skills`).
- `src/i18n/content/en-text.ts`: apresentação, história, FAQ, termos, patamares, maturidades e benchmarks em inglês.

Regras dos overlays:

- Campo ausente = texto em português. Um overlay pode ser parcial.
- Listas (`history`, `actors`, `equations`, `sources`) são **por posição**. A tradução precisa ter o mesmo número de itens e na mesma ordem do dado. `i18n.test.ts` compara o inglês com o português passo a passo.
- Ids dos overlays são os mesmos dos dados. `i18n.test.ts` confere que o id existe.
- Benchmarks: a tradução não muda números nem datas. Quem atualiza um placar atualiza os dois idiomas.

Acessores que devolvem o conteúdo no idioma atual:

| Conteúdo | Acessor |
| --- | --- |
| Habilidades | `localSkills()`, `localSkillById(id)` (`src/data/localized.ts`) |
| Benchmarks | `localBenchmarks()` (`src/data/localized.ts`) |
| Passos da apresentação e da história | `stepsOf(mode)` (`src/presentation/modes.ts`) |
| FAQ | `faqItems()`, `filterFaq()`, `glossary()` (`src/guide/faq.ts`) |
| Patamares e maturidades | `tierDetails()`, `statusDetails()` (`src/guide/levels.ts`) |

## Termos

Use os mesmos termos em toda a interface:

| Português | Inglês |
| --- | --- |
| habilidade | skill |
| área | area |
| patamar (T1 a T5) | tier |
| maturidade | maturity |
| gaveta | drawer |
| Como usar | How to use |
| Apresentação / História | Presentation / History |

Datas: o Vault mostra `dd/mm/aaaa` em português e `mm/dd/aaaa` em inglês (`formatDate` em `BenchmarkVault.tsx`). Ordenação de nomes ainda usa `pt-BR` em `src/lib/arrange.ts` e `src/lib/search.ts`; prefira o idioma atual em código novo.

## Checklist ao mexer em texto

1. Adicionou chave em `pt` e em todos os dicionários de `src/i18n/ui/`?
2. Usou `t()` em vez de texto fixo?
3. Se o texto depende do idioma, é uma função ou um acessor, não uma constante do módulo?
4. O inglês tem o mesmo número de itens nas listas?
5. `npx vitest run src/__tests__/i18n.test.ts` passa?
